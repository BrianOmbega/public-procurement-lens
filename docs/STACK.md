## Components the form asks about

**Agents.** One reviewing agent, `LensGraph` (`src/lens/graph.py`): it plans a review, retrieves
evidence, computes statistics, writes findings, validates its own citations, and stops at a human
gate. Deliberately *not* a multi-agent swarm — a single accountable agent over a fixed graph is
easier to audit, which is the point of the project. It is assisted by a borrowed upstream agent
server (`mcp-server-fetch`) reached over MCP.

**LLMs.** Swappable behind one interface (`src/lens/models.py`, `get_model()`), selected by env:
`scripted` (deterministic control, zero variance by construction), **Ollama open-weights**
(`qwen3:1.7b` verified on a full task; `qwen3:4b` attempted, failed on this machine's memory — see
`EVALS.md` row 9), and any **OpenAI-compatible** endpoint by `base_url`. Requests go out at
`temperature: 0.1`. Every LLM carries `.name`, so each audit event is attributed to the exact
weights that produced it.

**Memory.** Three distinct layers, because they do different jobs:
- *Working state*: `LensState` (TypedDict) accumulates plan → evidence → analysis → findings →
  validation → gate → artifacts as the graph advances.
- *Checkpointing*: LangGraph `InMemorySaver`, which is what lets the graph suspend at `interrupt()`
  and resume with full state after a human approves. Known limit, stated in `ARCHITECTURE.md`:
  cross-process resume needs `SqliteSaver`, path clear, not built.
- *Durable record*: the append-only JSONL audit trail (`src/lens/audit.py`), one event per action
  with `ts`, `kind`, `tool`, `model`, `session`, `request`, `response`, `approver`. Machine-checked
  by `lens-audit verify`.

**Orchestration.** LangGraph `StateGraph`, 8 nodes (`plan`, `retrieve`, `analyze`, `synthesize`,
`self_check`, `human_gate`, `finalize`, `fail`) and 4 conditional routers
(`route_after_retrieve/analyze/check/gate`). One router sends the graph **backwards** to
`synthesize` when citation validation fails, capped at `MAX_REPAIRS = 2`, then hard-fails rather
than shipping uncited work. The human gate uses `interrupt()` + `resume_with`.

**Tools.** Five own tools (`contract.TOOL_NAMES`) served by `lens-mcp` over **real MCP stdio**
(`McpBridge`, never in-process): three read (`search_awards`, `get_supplier_history`,
`analyze_price`) and two action (`draft_committee_brief`, `raise_flag`). `GATED_TOOLS` declares the
irreversible ones so "a gate on every irreversible action" is machine-readable rather than a
convention. Plus the borrowed official `mcp-server-fetch` (opt-in `--with-fetch`): maintained by the
MCP project, so redirect, robots.txt and encoding handling are not ours to break.

**Workflows.** `plan → retrieve → analyze → synthesize → self_check → human_gate → finalize`,
with `fail` reachable from any router. Entry points: `bash run.sh` (seed → validator negative test →
gated demo), `lens-demo`, `lens-ingest`, `lens-audit`, and `.github/workflows/ci.yml`. Stub and real
servers share `analysis.py` / `actions.py`, so parity is structural rather than copy-pasted.

**Databases.** SQLite (`data/`, gitignored, regenerated by `lens-ingest`). OCDS release packages are
streamed with `ijson` rather than loaded whole, into a corpus the MCP server opens **read-only** —
it can never write the corpus it cites. A `meta` table records provenance: sources, ingested and
skipped counts, skip reasons. Malformed records become `data_quality_notes` instead of crashing or
being silently dropped. *(TS side: JSONL append files via `node:fs`, plus Azurite in
docker-compose.)*

**APIs.** Outbound: MCP (JSON-RPC over stdio) to both tool servers; OpenAI-compatible
`/chat/completions` and Ollama's API via `httpx`; `tenders.go.ke` portal URLs (`PORTAL_BASE`)
embedded in citations so a human can click through to the source. Inbound: none on the Python side —
it is a CLI/graph, not a service. *(TS side: an express service on `:3000` exposing `/healthz`,
`/readyz`, `POST /mcp`, `POST /api/audit-events`.)*

## Deliberate absences

Stated because a reviewer will look for them:

- **No vector database / embeddings.** Item matching is substring-based; `ARCHITECTURE.md` lists
  embeddings or a normalized taxonomy as the known next step for a real corpus.
- **No award capability.** `ACTION_TOOLS` is exactly `draft_committee_brief` and `raise_flag`. The
  agent cannot award, rank or amend a tender, because no such tool exists in the contract.
- **No self-approval.** `validate_approver` rejects blanks, automation tokens, and the acting
  model's own name.
- **No live PPIP corpus yet.** The seeded corpus is the offline fixture set (10 releases) because
  `tenders.go.ke` bulk downloads 429 under probing. Pointing `lens-ingest` at a real package is a
  one-command swap behind the same contract, no code change.
